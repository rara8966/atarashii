# 首页项目库与用地标准库实施方案

## 1. 客户真实诉求

客户这次不是只要求“把土地用地标准文件放进系统”，而是要求系统从单个风电项目 Demo 升级为“多项目类型 + 项目档案 + 用地标准库驱动校验”的业务系统。

从截图和 `土地用地标准` 文件夹看，资料结构分为三层：

1. 原始扫描汇编：3 个 PDF，作为来源依据和备查材料。
2. 项目分类目录：电力、风电、石油天然气、煤炭、铁路、公路、民航机场、公共文化体育设施等。
3. 已提取的 DOCX 标准文本和核心表格合并文档：可直接转为系统标准库。

客户口头需求可拆成三件事：

1. 增加首页：创建项目、选择项目类型、生成系统编号、进入草稿箱、回查历史项目。
2. 真正落库：项目、文件、分析结果、标准库、标准匹配结果不能只存在前端或临时变量中。
3. 第六步土地利用嵌入用地标准库：根据项目类型和技术条件匹配对应指标，形成可追溯的标准校验结果。

## 2. 第一阶段交付目标

第一阶段先做可演示闭环，不一次性做复杂的全文 RAG 和全部参数计算。

必须完成：

- 首页项目列表和新建项目。
- 新建项目字段：项目名称、项目类型、建设单位、建设地点。
- 系统自动生成项目编号。
- 项目记录落到本地数据库。
- 首页可进入项目工作台。
- 用地标准库落库，支持按项目类型浏览和搜索。
- 第六步展示当前项目类型匹配到的标准库条目。
- 上传材料分析后，标准库校验结果可保存和回查。

暂缓到第二阶段：

- 每一类项目的精确公式计算。
- 从 PDF 原始扫描件重新 OCR。
- 复杂多条件插值计算。
- 多用户权限、审批流、云端数据库。

## 3. 技术路线

考虑客户电脑需要 EXE 版运行，不要求客户安装数据库，第一阶段采用内嵌 H2 文件数据库。

数据库文件放在：

```text
data/policy-report-demo-db.mv.db
```

优势：

- 客户电脑无需安装 MySQL。
- EXE 版可以直接运行。
- 数据真正持久化到本地文件。
- 后续正式部署可迁移到 MySQL。

## 4. 数据模型

### 4.1 项目表 `project_record`

字段：

- `id`：项目 UUID。
- `project_code`：系统编号，例如 `PRJ-20260509-0001`。
- `project_name`：项目名称。
- `project_type`：项目类型编码。
- `project_type_label`：项目类型名称。
- `owner`：建设单位。
- `location`：建设地点。
- `status`：草稿、分析中、已生成报告。
- `created_at` / `updated_at`：创建和更新时间。

### 4.2 标准库表 `land_use_standard`

字段：

- `id`：标准条目 UUID。
- `project_type`：项目类型编码。
- `project_type_label`：项目类型名称。
- `source_file`：来源 DOCX 文件名。
- `chapter_title`：章节或表名。
- `content`：标准条文/表格文本片段。
- `keywords`：检索关键词。

### 4.3 标准校验结果表 `land_use_standard_match`

字段：

- `id`：匹配结果 UUID。
- `project_id`：项目 ID。
- `standard_id`：标准条目 ID。
- `match_status`：通过、需关注、缺参数。
- `matched_fields`：匹配到的项目参数。
- `conclusion`：系统生成的校验结论。
- `created_at`：生成时间。

## 5. 标准库导入规则

第一阶段不导入 3 个大 PDF，只导入已提取 DOCX：

- `建设用地指标（各工程核心表格合并）.docx`
- 8 类项目目录下的 DOCX 标准文件

导入方式：

1. 系统启动时检查标准库表是否为空。
2. 为空则从内置种子数据导入标准条目。
3. 标准条目按项目类型、章节、表格标题切分。
4. 首页和第六步可直接查询标准库。

## 6. 前端页面变化

### 6.1 首页

首页是工作台入口，不做营销页。

首页包含：

- 顶部系统名称和状态概览。
- 新建项目表单。
- 项目类型选择。
- 草稿项目列表。
- 点击项目进入八步审查工作台。
- 标准库数量和当前支持项目类型。

### 6.2 工作台

工作台顶部显示当前项目：

- 项目名称
- 系统编号
- 项目类型
- 返回首页按钮

第六步增加“用地标准库匹配”模块：

- 当前项目类型对应标准数量。
- 可搜索标准条目。
- 展示来源文件、章节、标准文本。
- 保存/刷新校验结果。

## 7. 成功标准

完成后必须验证：

1. 后端测试通过。
2. 前端构建通过。
3. 启动后首页能新建项目。
4. 刷新页面后项目仍存在。
5. 标准库接口能返回风电、公路等分类标准。
6. 第六步能展示当前项目类型的标准库匹配内容。
7. EXE 打包脚本仍能生成可运行包。

## 8. 本轮实现边界

本轮先完成“项目首页 + H2 落库 + 标准库基础导入 + 第六步标准库展示”。

如果时间允许，再补标准匹配结果保存和首页回查摘要。
